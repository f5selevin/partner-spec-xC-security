Review API request and security analytics
#########################################

Review the events generated by the API validation, endpoint-denial, and rate-limit tests.

Requests dashboard
~~~~~~~~~~~~~~~~~~

1. Go to **Web App & API Protection** > **Overview** > **Security**.
2. In **Delivery Resources**, select the ``arcadia-finance`` HTTP load balancer and open **Requests**.
3. Set the time range to include all tests, apply it, and refresh the view.
4. Filter and compare the following paths:

   * ``/banks``
   * ``/internal/shadow-report``
   * ``/user/profile``
   * ``/accounts``

5. Open representative allowed and denied requests. Compare status, method, source, request ID, latency, and enforcement metadata.

Security Analytics dashboard
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. Open **Security Analytics** for the same load balancer and time range.
2. Locate and inspect events for:

   * An unknown path blocked by the API fall-through rule.
   * An unsupported method blocked by API validation.
   * An invalid request body blocked by schema validation.
   * ``/user/profile`` denied by the explicit endpoint rule.
   * ``/accounts`` rejected by API rate limiting.

3. Use filters or forensics to isolate each control. Record the violation or rule name, action, response code, and request ID.
4. Confirm that WAF and Bot Defense events remain distinguishable from API Protection and rate-limit events.

Malicious User Detection may assign risk based on repeated abusive behavior if it is enabled in the tenant, but enabling or tuning that feature is outside this API Security exercise.
